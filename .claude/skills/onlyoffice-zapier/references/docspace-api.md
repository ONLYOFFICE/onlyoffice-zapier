# DocSpace API 4.0 — what the integration relies on

Sources: the DocSpace-server sources (`v4.0.0-server`), api.onlyoffice.com and checks on a live 4.0 workspace. Items
marked "unchecked" come from the sources or the docs only. Docs: `https://api.onlyoffice.com/docspace/api-backend/…`
(no trailing slash; the README links point there).

## Envelope and lists

- Every response is `{ response, count, total?, links, status, statusCode }`; `Client.request` returns `response`.
- `count` is 1–100 (more gives 400). Page with `count` + `startIndex`; `total` tells when to stop.
- A valid `sortBy` in a request is saved as the user's default sort order in the DocSpace interface. Don't send it
  where the order doesn't matter (dropdowns, searches); sort on our side instead. Without `sortBy` the order is the
  user's saved one.
- `filterValue` searches by title (people: by name and email) and matches substrings.
- `GET /files/{folderId}` takes `filterType` (`FilesOnly`, `FoldersOnly`), `withSubFolders`, `filterValue`,
  `searchArea`, `count`, `startIndex`, `sortBy`, `sortOrder`.
- `GET /files/rooms` returns active rooms without Form filling rooms. Other areas: `searchArea=Forms` (Form filling
  rooms), `Archive`, `Templates`.

## Rooms, folders, files

- Rooms have no Trash: deleting a file or folder in a room is permanent. The Files section has Trash; `immediately`
  skips it.
- Async operations return an operation (`id`, `progress`, `finished`, `error`, `files`, `folders`) and are polled with
  `GET /files/fileops`: archive / unarchive (`PUT /files/rooms/{id}/archive|unarchive`), delete
  (`DELETE /files/file/{id}`, `DELETE /files/folder/{id}`), move / copy (`PUT /files/fileops/move|copy`, with a
  conflict mode), duplicate (`PUT /files/fileops/duplicate`, also duplicates a room when `folderIds` has its id).
- Room templates: `GET /files/rooms?searchArea=Templates`, create a room with `POST /files/rooms/fromtemplate` and poll
  `GET /files/rooms/fromtemplate/status`. DocSpace keeps one such operation per account.
- Convert: `POST /files/file/{id}/copyas` with `destTitle` and `destFolderId`; the target formats are in
  `GET /files/settings` → `extsConvertible[".docx"]`.
- Text files: `POST /files/{folderId}/text` (.txt) and `…/html`.
- Upload: `POST /files/{folderId}/session` creates a session, then the chunks go to
  `{baseUrl}/ChunkedUploader.ashx?uid={sessionId}`. `…/upload/create_session` is obsolete.
- Download: `GET /files/file/{id}/presigned` returns a temporary URL for the Document Server host. On self-hosted
  workspaces that host can be internal (unchecked).
- Lock: `PUT /files/file/{id}/lock` with `lockFile`.
- Ids of files and folders in third-party storage are strings (`sbox-1-…`).
- Entries carry a `security` object with flags of what the current user may do (`Create`, `Delete`, `Rename`,
  `EditRoom`, `EditAccess`, `Move`, `Copy`, `Lock`, `CopyLink`, …).

## Links

- `GET /files/rooms/{id}/link`, `/files/file/{id}/link`, `/files/folder/{id}/link` return the primary external link and
  **create it if there is none**. `GET …/links` lists the links without creating one. A revoked link gives 404.
- Room links exist in Custom and Public rooms (one primary + additional) and Form filling rooms (primary). Collaboration,
  Virtual Data and AI rooms have none. File and folder links get the room's default access: public in Collaboration
  rooms, only for workspace users in Virtual Data Rooms.

## Sharing and members

- `PUT /files/rooms/{id}/share` with `{ invitations: [{ id | email, access }], notify, message }`. Access 0 removes a
  member. DocSpace silently drops subjects the caller can't see and gives the same answer when it ignores a change (for
  example, removing the owner), so check the members afterwards.
- `GET /files/rooms/{id}/share` lists users and groups (`sharedToUser` / `sharedToGroup`; `sharedTo` is obsolete);
  `filterValue` matches substrings, so compare emails exactly.
- Inviting by email creates a Guest; the workspace must allow guest invitations.

## People

- `GET /people` returns only active users; `GET /people/email?email=` finds any user by email (404 if none).
- `POST /people/invite`: a Room admin can invite Users, a Full admin also Room admins, the owner also Full admins.
- User type: `PUT /people/type/{type}` for Room admin / Full admin; for User and Guest it returns 403, use
  `POST /people/type` and poll its progress. Room admins and Full admins take a paid seat (402 without seats).
- Status: `PUT /people/status/{Active|Terminated}`.

## Webhooks

- `POST /settings/webhook` `{ name ≤50, uri, secretKey, enabled, ssl, triggers }`, `DELETE /settings/webhook/{id}`.
  DocSpace checks the URI with an empty request first.
- `secretKey` must pass the workspace password policy; passwords are at most 30 characters.
- `triggers` is a mask that doesn't fit in 32 bits: sum the flags, don't use `|`.
- Signature: `x-docspace-signature-256: sha256=<HEX UPPERCASE>`, HMAC-SHA256 of the raw body with the secret key.
- Body: `{ event: { trigger, … }, payload, webhook }`. The payload is the internal entry (`id`, `parentId`,
  `rootFolderType`, `title`, …), not the API DTO; `form.submit` sends `{ originalForm, submittedForm }`.
- Delivery: retries with backoff; a 410 answer deletes the webhook; events while it is off are lost; order isn't
  guaranteed. Events come only for entries the webhook owner can see.
- Only Full admins and Room admins can subscribe to `user.*`, `group.*`, `room.created`, `room.copied`,
  `agent.created`. Guests can't use webhooks; Users only when developer tools aren't restricted.

## Rights

- User types: Owner, Full admin, Room admin, User, Guest. Room manager is a paid role: only Room admins and above can
  have it.
- Rights on files and folders come from the role in the room, not from the user type. A Full admin who isn't a member
  of a room sees it but can't archive it, rename or delete in it (unchecked in full).
- Create, upload, convert, copy: Room manager, Content creator. Rename, delete: Room manager; Content creator only own
  entries. Move: Room manager. Archive, unarchive, members, room links: Room manager. Tags: Room manager or a
  workspace admin.
- Guests have no Files section; most actions in rooms fail for them.
